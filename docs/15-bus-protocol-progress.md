## Отчёты по этапам

### Этап 1. Протокол и применитель

**Сделано.**
- `core/bus/protocol.ts`: константы потоков, ключи `event`/`changes`, типы `DataChange`,
  `BusChangesMessage`, `BusCompletion`.
- `core/bus/applier.ts`: `applyChanges` — атомарное применение изменений одной операции, состояние
  вместо дельты, защита по `updatedAt`, составной ключ у `UserRole`, `Prisma.DbNull` для null в Json.
- `apps/agent`: обменники и очередь применения объявляются при старте; отдельный канал с prefetch 1
  применяет изменения по порядку и публикует COMPLETION; за каждую запись через MAIN тоже
  публикуется COMPLETION (универсально, осмысленно и без второго агента).
- `core/bus/busPort.ts`: приложение слушает EVENTS по ключу `event`.
- `tools/protocol-smoke.ts` и шаг CI: внешний издатель шлёт изменения так же, как будет агент №2.
  Проверяется применение, повтор, устаревший и более новый снимок, удаление, цепочка с внешними
  ключами, составной ключ, Json-null, ошибка применения и продолжение работы после неё,
  подтверждение за запись через MAIN.

**Не сделано / честно.** Агент №2 пока работает по старой схеме (прямое дублирование), в его коде
исправлено только объявление обменника. Проверка идёт на одной базе.
