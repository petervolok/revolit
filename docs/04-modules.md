# Модули

## Зачем

Расширять возможности, не переписывая ядро. Модуль объявляет, что он добавляет,
ядро подключает его само.

## Устройство модуля

Каждый модуль везёт **описание** — что он приносит в систему:

```
Модуль «CRM-конструктор»
├── название, версия, требуемая версия ядра
├── зависимости от других модулей
├── пункты меню
├── страницы и адреса
├── права доступа
├── сущности и поля
├── разделы настроек
├── задания по расписанию
├── подписки на события
└── изменения структуры базы
```

Ядро читает описание при запуске и собирает систему.
Реестр установленных модулей хранится в базе — модуль можно включить и отключить.

## Список модулей

| Модуль | Что даёт | Стоимость | Состояние |
|---|---|---|---|
| **Ядро** | Оболочка, вход, роли, журнал, сущности | бесплатно | частично готово |
| **CRM-конструктор** | Сборка систем из сущностей и рабочих мест | бесплатно | планируется |
| **CMS + сайт** | Управление контентом, витрина для посетителей | бесплатно | планируется |
| **ИИ-сборка** | Сборка конфигурации по описанию словами | платно | планируется |
| **Маркетплейс** | Установка модулей сторонних разработчиков | платно | планируется |
| **Корпоративный вход** | Вход через каталог компании | платно | планируется |
| **Телефония, мессенджеры** | Каналы связи изнутри системы | платно | обсуждается |

## Бесплатно и платно

**Принцип:** малому бизнесу хватает бесплатного. Платят те, кому возможности реально нужны
и кто способен платить. Это классическая граница, проверенная отраслью.

### Бесплатно

- ядро целиком
- ручной конструктор
- базовые сущности
- самостоятельная установка на свой сервер

### Платно

- **ИИ-сборка** — самая ценная часть замысла
- **Маркетплейс** модулей
- **Корпоративный вход** (LDAP, SAML, единый вход)
- **Поддержка**
- **Облако по подписке**
- **Выгрузка готового образа** из облака к себе

**Важно для структуры проекта:** платные модули должны быть отдельными пакетами,
чтобы их можно было не включать в бесплатную поставку. Разделять потом — дороже,
чем заложить сразу.

## Корпоративный вход — пояснение

Вход в систему не через отдельный пароль, а через учётную запись, которая уже есть
у сотрудника в компании.

**Зачем компаниям:**
- уволили человека — отключили в каталоге, доступ пропал везде сразу;
- сотрудники подтягиваются из корпоративного справочника, не заводятся вручную;
- правила паролей задаёт служба безопасности компании;
- часто обязательное условие закупки для крупных клиентов.

**Что входит:** Active Directory и LDAP (основной случай для коробки),
SAML и OpenID Connect, вход через Яндекс ID и VK ID для небольших компаний.

**Не путать** с двухфакторной аутентификацией — она в бесплатном ядре и работает всегда.
Корпоративный вход не «безопаснее», а удобнее в управлении при большом штате.

## Модули сторонних разработчиков

Публикуются в маркетплейсе. Требования:

- объявляют совместимую версию ядра;
- пользуются только опубликованным интерфейсом ядра;
- везут свои изменения структуры базы;
- не ломают систему при сбое — несовместимый модуль просто не включается.

Изоляция сбойных модулей и безопасный режим — задача не первой очереди,
но заложена в замысел.
