# Соглашения по разработке

## Язык

- **Интерфейс** — русский.
- **Комментарии в коде** — русские, объясняют *почему*, а не *что*. То, что видно
  из кода, не комментируем.
- **Названия в коде** — латиница, общепринятые для стека.
- **Документация** — русская.

## Оформление интерфейса

Ориентир — современные системы уровня Linear, Attio, Pipedrive: спокойно, без визуального
шума, много воздуха.

**Правила:**
- цвета, отступы и размеры берём из общей системы стилей, не пишем поштучно;
- поддерживаем светлую и тёмную темы — новый элемент обязан выглядеть прилично в обеих;
- состояния обязательны: загрузка, пустой список, ошибка. Пустой экран без объяснения —
  недоделка;
- разрушительные действия отмечаются цветом и требуют подтверждения;
- клавиатура: Esc закрывает панели, видимая рамка фокуса не убирается.

**Готовые элементы** лежат в `src/components/ui/` — кнопки, поля, значки, флажки,
выезжающая панель, меню строки, пустое состояние. Новые элементы добавлять туда же,
а не переписывать на месте.

## Разграничение доступа

Каждый новый раздел закрывается на **трёх уровнях**:

1. обработчик запроса — `requirePermission()`;
2. страница — `requirePageAccess()`;
3. пункт меню — по праву в описании.

**Скрытие пункта меню защитой не считается.** Главный рубеж — обработчик запроса.

## Работа с базой

- изменения структуры — только через миграции, руками в базе ничего не правим;
- каждый модуль везёт свои изменения;
- удаление данных пользователя — только с явным подтверждением;
- в журнал действий пишем всё, что меняет доступ или удаляет данные.

## Безопасность

- пароли, коды и токены хранятся **только хешами**;
- ответы не должны раскрывать существование учётной записи;
- новый обработчик запроса начинается с проверки прав;
- секреты — в переменных окружения, **не в файлах проекта**.

## Особенности этого окружения

Записаны, потому что стоили времени.

### Папка проекта синхронизируется в облако

`D:\YandexDisk\...` уходит в Яндекс.Диск. **Секреты в файлы проекта не пишем.**
Файл `.env.prod` добавлен в список игнорируемых.

### Сервер разработки не видит новые файлы

Docker на Windows не доносит уведомления об изменениях. Создали новый файл страницы
или обработчика — он отдаёт «страница не найдена», хотя лежит на месте.

**Лечится:**
```bash
docker compose restart app
```

Правки существующих файлов подхватываются нормально. На сервере такого нет —
там программа собирается целиком.

### Кириллица ломается в командной строке

Git Bash под Windows портит русские буквы при передаче в запросах. Имя «Иван Петров»,
отправленное командой из консоли, попадает в базу мусором.

**Правило:** проверочные данные вводим латиницей, а если нужна кириллица —
через скрипт, запущенный внутри контейнера.

### Перенос кода на сервер архивом затирает секреты сервера локальными

Перенос через `tar` + `scp` (нет git, переносить нечем кроме архива) захватывает
и локальный `.env.prod`, если явно не исключить его. У сервера пароль базы свой,
не совпадает с тем, что лежит в файле на рабочей машине, — простая перезапись
может подменить рабочий пароль на устаревший, и после пересоздания контейнеров
приложение не подключится к уже существующей базе (пароль в Postgres задаётся
один раз при первом запуске тома и переменной окружения больше не меняется).

**Правило:** при переносе исходников архивом всегда исключать `.env` и `.env.prod`
(`tar --exclude='.env*'`) — эти файлы у каждого окружения свои. Если всё же
затёрли — актуальный пароль ещё жив в переменных окружения уже запущенного
контейнера, пока его не пересоздали: `docker exec <контейнер_бд> printenv POSTGRES_PASSWORD`.

### Панель выезжающей формы не анимируется в невидимой вкладке браузера

Автоматизированная проверка в браузере рисует страницу во вкладке, которую пользователь
не открыл на экране. Chrome не считает такую вкладку видимой и не запускает CSS-переходы
в ней — класс переключается верно, а сама анимация (`transition-transform`) замирает
на стартовом кадре. Кнопка внутри панели физически остаётся за пределами экрана,
и клик по ней инструментом автоматизации закономерно не попадает в цель.

К самому продукту отношения не имеет — у живого пользователя вкладка всегда видна.

**Правило:** если клик по кнопке в выезжающей панели не проходит при автоматической
проверке, не считать это дефектом вёрстки без предварительной проверки. Первым делом
посмотреть `document.visibilityState` страницы. Если `hidden` — либо явно вывести
вкладку на передний план перед кликом, либо проверять результат действия напрямую
через `fetch` из контекста страницы (так сохраняется сессия входа) и через журнал
запросов сервера, не дожидаясь завершения анимации.

### Docker Desktop падал дважды

Повреждались внутренние данные и оставался зависший файл. Лечится перезапуском,
в тяжёлом случае — перезагрузкой машины. Локальная база при этом может испортиться —
пересоздаётся.

## Локальный запуск

```bash
docker compose up -d
```

| Что | Адрес |
|---|---|
| Программа | http://localhost:3210 |
| Перехватчик почты | http://localhost:8026 |
| База | localhost:15432 |

Учётная запись для разработки: `admin@revolit.local` / `Revolit2026admin`

**Только для локальной работы.** На сервере такой записи быть не должно.

Полезные команды:

```bash
docker compose exec app npx prisma migrate dev
```

```bash
docker compose exec app npx prisma db seed
```

```bash
docker compose exec app npx tsc --noEmit
```

## Проверка работы

- **Проверка типов обязательна** перед завершением задачи — она ловит большую часть ошибок.
- Сценарии входа и прав проверяются запросами, а не только глазами.
- Автоматических тестов пока нет. Появятся, когда стабилизируется ядро —
  начинать с входа и разграничения доступа.

## Порядок работы

1. Сверились с [дорожной картой](07-roadmap.md).
2. Крупная задача — сначала обсуждение подхода, потом код.
3. Приняли решение — записали в [журнал решений](08-decisions.md) с обоснованием.
4. Сделали — проверили типы и живой сценарий.
5. Изменилось устройство — обновили соответствующий документ.

**Правило про отчётность.** О сделанном сообщаем честно: что работает, что не проверено,
что осталось заглушкой. Заглушка, поданная как готовая функция, обходится дороже
несделанной работы.
