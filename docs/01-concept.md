# Концепция продукта

## Суть

Платформа для сборки корпоративных систем без программирования.

Не готовая CRM, которую подгоняют под себя, а **инструмент, которым систему делают под задачу**.
Пользователь описывает бизнес-процесс — получает работающую программу с меню, формами,
таблицами, ролями и правами.

Два уровня работы:

1. **Ручная сборка** — визуальный конструктор: перетаскиваем блоки, получаем разделы.
2. **Сборка с ИИ** — описываем задачу словами, ИИ собирает конфигурацию, человек правит.

## Модель бизнес-процесса

```
Бизнес-процесс
└── Этап
    └── Рабочее место     ← за ним закреплены регламент и требуемые навыки
        └── Блоки действий ← карточки, отчёты, отправка документов
```

**Рабочее место** — ключевое понятие. За каждым закреплён регламент (что делать) и
описание навыков (что нужно уметь). Исполнителем может быть человек **или подключаемый
ИИ-агент** с этими навыками. Это заложено в модель с самого начала.

## Кто пользователь

| Роль | Что делает |
|---|---|
| **Сборщик** | Проектирует систему в конструкторе: сущности, рабочие места, права |
| **Сотрудник** | Работает в собранной программе: заполняет карточки, смотрит отчёты |
| **Администратор программы** | Заводит сотрудников, назначает им роли |
| **Сторонний разработчик** | Пишет модули и публикует их в маркетплейсе |

Важно: **сотрудник о конструкторе не знает**. Он входит в свою программу и видит
только рабочие разделы.

## Целевые случаи

Взяты из исходного задания, служат проверкой полноты платформы:

1. **Центр сертификации.** Карточки документов и счетов, связи между ними, контрагенты,
   наличные расчёты и премии. Руководитель ведёт своих клиентов скрытно от менеджеров,
   отмечает оплаты, смотрит отчёты. Напоминания об истечении срока документов.

2. **Банкетный ресторан.** Заказ банкета: клиент, зал, дата, меню из справочника.
   Формирование PDF и отправка клиенту на согласование. Передача заказа другому менеджеру.
   Напоминания о прошлогодних банкетах. Отдельный отчёт для кухни. Календарь банкетов на
   главной. Управляющий правит меню и схемы залов с расстановкой столов.

3. **Маркетинговое агентство.** Проекты с анкетами и сроками, аналитика в SPSS, сведение
   баз в единое хранилище, автоматическое построение отчётов и презентаций, кабинет клиента.

4. **Центр сертификации с внешними каналами.** Работа с клиентом через почту и мессенджеры
   изнутри системы, ИИ-консультант, отслеживание этапов, кабинет клиента с планом работ,
   рассылки и обзвоны.

## Второй продукт: CMS

На том же ядре строится конструктор сайтов. Слева — разделы управления контентом,
справа — страницы редактирования, сам сайт отображается отдельно для посетителей.
Структура сайта и наполнение создаются с участием ИИ, дальше правятся вручную.

**Решение:** отдельный сервис со своей базой, общее — только ядро.
См. [архитектуру](02-architecture.md).

## Позиционирование

### Чем это не является

Это **не конкурент Битрикс24 в лоб**. Соперничать по объёму возможностей с продуктом,
который развивают пятнадцать лет сотни разработчиков, бессмысленно. У Битрикса телефония,
задачи, документы, интеграция с 1С, мобильные приложения, тысячи партнёров-внедренцев
и репутация безопасного выбора для закупки.

### Где настоящее поле

Категория другая — **конструктор, а не готовая CRM**. Соседи по рынку: Directus, Retool,
Budibase, n8n, Airtable. В России ниша заселена значительно реже.

Слабости Битрикса, которые дают шанс:

- перегруженный интерфейс, простые задачи требуют много действий;
- любая доработка — через платного партнёра, клиент попадает в зависимость;
- универсальность вместо глубины: отраслевые задачи закрываются натужно.

### Реалистичные пути

1. **Одна отрасль всерьёз** — сделать так, чтобы человек из неё сказал «это про нас».
   Конкурент здесь не Битрикс, а Excel и бумага.
2. **Продавать внедренцам** — тем, кто сейчас неделями настраивает Битрикс под заказчика.
3. **Скорость изменений** — правка в конструкторе против сметы на две недели.

### Чего не хватает даже для нишевого выхода

Задачи и напоминания, календарь, почта и мессенджеры внутри системы, отчёты, импорт
данных, мобильный доступ. Это месяцы работы — учитывать при планировании.

Пока внятного ответа нет, сравнение с существующими продуктами преждевременно.
